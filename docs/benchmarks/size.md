# Benchmark results: bytes per value

Generated by `mise run bench:size`; do not edit by hand.

Each cell is the serialized size of one sample value of the shape, in bytes,
with its ratio against surge; every library encodes the same value. An empty
cell means the library cannot express the row.

`+N side` means N values travel outside the buffer (the blob array in surge,
fbs, serio and flamework2; the instance table in Zap), which costs bandwidth
the byte count does not show.

`Round trip` names each library whose decoded value differs from the input,
with the largest difference in any component. About 1e-7 is f32 rounding of
a `CFrame` rotation, and about 1e-4 a quantized one. A difference near 1 is a
loss in the library or in this runner, which
[research/serialized-size-across-libraries.md](../research/serialized-size-across-libraries.md)
explains.

Blink and Zap are smaller than surge only where a length prefix appears:
they default to a u16 count where surge writes u32, and `DataType.Length`
narrows surge's.

`flamework2` is `Flamework.createSerializer` of `@flamework-experimental/core` 2.0.0-alpha.8,
an experimental Flamework 2. It writes each count and length as a varint, one
byte below 128, an enum item as a u16 of its `Value`, a `CFrame` as its twelve
components, and a blob's index into the buffer as a u32. It has no `Packed`.

`baseline` is a hand-written codec that writes surge's exact bytes on five
rows; it exists for the speed table. Zap's bytes are one fired event minus
its event-id byte.
