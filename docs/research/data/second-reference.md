Not the committed table: this is a second run of the reference build,
unchanged, kept as the data behind
[tables-around-serialize.md](../tables-around-serialize.md). It measures how
far two invocations of one build land apart in one session. Read it only
against the reference run recorded at surge `56b6fd5`.

Each figure is the geometric mean of that library's throughput against
surge's over the rows both have: above 1.00× is faster than surge.

Each cell below is a median throughput over 2 runs back to back. `±` is
the middle half of its trials, as a fraction of the median. Between the
runs, no cell moved by more than 17% and nine in ten by under 7%; a
difference narrower than that is noise. A cell marked † spread or moved
by more than 10% and is left out of the summary.

Time per value is the same measurement as microseconds per call, which
reads across rows where a rate does not.

`baseline` is a hand-written codec that writes surge's exact bytes on
three rows, so its ratio is what surge's generated code costs against
hand-written Luau. Zap exposes no encoder to call and has no column.
Every column but serio runs with `--!native` and `--!optimize 2`.

Each number is one shape in a warm loop, on one machine on one day, not
an application profile; compare columns within this file only.
[size.md](../../benchmarks/size.md) gives each row's bytes, and
[specs/benchmark-harness.md](../../specs/benchmark-harness.md) says how the suite measures.
