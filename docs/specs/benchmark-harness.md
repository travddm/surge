# Benchmark harness specification

Status: current
Applies to: `@rbxts/surge` at commit `a551981`, `rbxts-transformer-surge` at
commit `925e701` (no tagged release yet)

## 1. Scope

This specifies the benchmark harness: the catalog of shapes, the libraries it
compares and how each is driven, the size and speed tiers and the protocol
each follows, the lines that carry a result out of Roblox, and what each
results file records. How to run a tier and read a result is in
[../testing.md](../testing.md). What the results show is under
[../research/](../research/README.md).

## 2. Terms

- **Row**: one shape in the catalog, a module under
  `tests/src/bench/fixtures/`.
- **Column**: one library, or the hand-written baseline.
- **Cell**: one column's measurement of one row, for one half — encode or
  decode.
- **Trial**: one timed measurement of a cell.
- **Run**: one pass of the speed suite over the catalog in one Studio
  process.
- **Invocation**: one `mise run bench:speed`, which is two runs back to back.
- **Scoped run**: a run over only the rows a pattern selects.

## 3. The catalog

**3.1** The catalog is the 16 rows `CATALOG` in `tests/src/bench/catalog.ts`
lists, and both tiers read it.

**3.2** A row holds one sample value, built with the seeded `Rng` where it
needs bulk data so that it is reproducible, and declares its shape once per
library, because each library brands widths with its own types. Widths are
explicit in every declaration.

**3.3** Every column is driven through the same interface:

```ts
interface Adapter<T> {
	encode: (value: T) => { bytes: number; side: number; payload: unknown };
	decode: (payload: unknown) => T;
}
```

**3.4** A column with no declaration for a row has no cell there, and the
tables show that cell empty.

## 4. The columns

**4.1** surge is driven through `createBinarySerializer<T>()`, fbs through
its `createBinarySerializer<T>()`, and serio through its default-exported
`createSerializer<T>()`.

**4.2** Blink is driven through the `Write` and `Read` its compiler generates
for each exported struct, from `tests/src/bench/definitions/catalog.blink`.

**4.3** Zap has no callable encoder. Its bytes are the payload one event
fired at a mocked remote hands `SendEvents`, less the event-id byte, and
`opt tooling` decodes them. That remote exists only under Lune, so Zap is a
size column only: `SIZE_ONLY` in `tests/src/bench/adapter.ts` keeps the speed
suite off it.

**4.4** The Blink and Zap definitions, `catalog.blink` and `catalog.zap`,
declare the same rows and override a default width only where the row's
TypeScript declaration brands one. Their compiled modules under
`tests/src/bench/blink/` and `tests/src/bench/zap/` are checked in and
regenerated by `mise run bench:definitions`.

**4.5** The baseline column is hand-written Luau in
`tests/src/bench/baseline/codecs.luau`, over three rows: the small flat
struct, the deeply nested object and the `CFrame` array. It must write
surge's bytes exactly, so that its timing measures code rather than format.

**4.6** Every column but serio's runs with `--!native` and `--!optimize 2`:
surge's fixtures and the baseline carry both, and fbs and Blink carry both on
the modules their codecs run in, as each ships.

## 5. The size tier

**5.1** `mise run bench:size` runs under Lune through
`tests/scripts/lune-size-runner.luau` and the same shim the round-trip suite
uses ([test-harness.md](test-harness.md)).

**5.2** For each cell it records the buffer's length in bytes, the number of
values passed outside the buffer, and the largest difference between any
component of the value and its round trip.

**5.3** It writes `docs/benchmarks/size.md`, which records no date, machine
or commit, so that the file changes only when an encoding does.

## 6. The speed tier

**6.1** `mise run bench:speed` builds the tests place and runs the speed
suite, `tests/src/bench/speed.spec.ts`, twice back to back in a Roblox Studio
process, through `run-in-roblox` and the injected script
`tests/scripts/run-in-roblox-benchmarks.luau`. It never runs under Lune.

**6.2** Each library of a row is first warmed up with 0.1 s of calls. Each
cell then gets nine trials, taken with the row's libraries in turn, one trial
each.

**6.3** A trial is at least 0.2 s of measured calls, timed in chunks of 250
calls, and ends at the first chunk boundary past 0.2 s. Its result is calls
over measured time. Every encode call encodes the row's one sample value,
every decode call decodes the one buffer encoded from it before timing began,
and each call's result is discarded.

**6.4** The suite yields between two chunks once 0.25 s of measured work has
passed since it last yielded, and never inside a timed chunk. It yields three
idle frames between one row and the next.

**6.5** The suite runs the encode and decode halves as one fact, and
`runBenchmarks` returns only after runit's verdict, because `run-in-roblox`
ends the run when the injected script returns.

## 7. Sentinel lines

**7.1** The speed suite prints one `BENCH_ENV:` line describing its method
as its module loads, and one `BENCH_ROW:` line per row, library and half,
carrying every trial's rate.

**7.2** `runBenchmarks` prints `BENCH_RESULT: PASSED` or `BENCH_RESULT: FAILED`
with runit's verdict.

## 8. The speed results files

**8.1** `tests/scripts/record-speed-benchmarks.mjs` wraps `run-in-roblox`,
forwards every line, and writes `docs/benchmarks/speed.md` and
`docs/benchmarks/speed-trials.tsv` only if every run printed
`BENCH_RESULT: PASSED` and returned every row in both halves. An interrupted
invocation leaves both files as they were.

**8.2** Both files record the date, the machine, the engine version the
process reports, and the commit or version of everything measured. A
repository whose working tree differs from its commit is marked as having
uncommitted changes.

**8.3** `speed-trials.tsv` holds every trial of every run.

**8.4** A cell in `speed.md` is the median of its trials across both runs.
Its `±` is the interquartile range of those trials over the median. The file
states how far cells' medians moved between the two runs.

**8.5** A cell whose spread or whose movement between runs exceeds 10% is
marked `†` and left out of the summary. The summary gives, per library and
half, the geometric mean of that library's throughput over surge's across
the unmarked rows both have.

**8.6** `mise run bench:speed:render` rewrites `speed.md` from
`speed-trials.tsv` without a run.

## 9. Scoped runs

**9.1** `mise run bench:size:only` and `mise run bench:speed:only` take
patterns and run only the rows they select. A pattern selects a row when,
with case and every character that is not a letter or digit removed from
both, the pattern is contained in the row's name. Both tiers select through
`tests/src/bench/selection.ts`.

**9.2** A scoped run prints its tables and writes no results file. A scoped
speed run is one run, not two.

**9.3** A `:only` task given no pattern, or a pattern that selects no row,
stops without measuring.

## 10. Rebuilding before a run

**10.1** Both tiers run `tests:install` and `tests:compile` before measuring,
for the reasons in section 6 of [test-harness.md](test-harness.md).
