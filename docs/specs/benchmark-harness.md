# Benchmark harness specification

Status: current
Applies to: `@rbxts/surge` at commit `b7b0746`, `rbxts-transformer-surge` at
commit `7422117` (no tagged release yet)

## 1. Scope

This specifies the benchmark harness: the catalog of shapes, the libraries it
compares and how each is driven, the size and speed tiers and the protocol
each follows, the lines that carry a result out of Roblox, and what each
results file records. How to run a tier and read a result is in
[../testing.md](../testing.md). What the results show is under
[../research/](../research/README.md).

## 2. Terms

- **Row**: one shape in the catalog: a `Fixture` that a module under
  `tests/src/bench/fixtures/` exports. One module may export more than one
  row.
- **Column**: one library, or the hand-written baseline.
- **Cell**: one column's measurement of one row. In the speed tier, a cell is
  also one half: encode or decode.
- **Trial**: one timed measurement of a cell.
- **Run**: one pass of the speed suite over the catalog in one Studio
  process.
- **Invocation**: one `mise run bench:speed`, which is two runs back to back.
- **Scoped run**: a run over only the rows a pattern selects.

## 3. The catalog

**3.1** The catalog is the 16 rows `CATALOG` in `tests/src/bench/catalog.ts`
lists, and both tiers read it.

**3.2** A row holds one sample value, built with the seeded `Rng` where it
needs bulk data so that it is reproducible. The large record is the one
exception: fbs and serio take its pairs as a `Map`, and every other column
takes the same pairs as a table.

**3.3** Every column is driven through the same interface:

```ts
interface Adapter<T> {
	encode: (value: T) => { bytes: number; side: number; payload: unknown };
	decode: (payload: unknown) => T;
}
```

**3.4** A column with no declaration for a row has no cell there, and the
tables show that cell empty.

**3.5** A row declares its shape for surge, fbs and serio with each library's
own width brands. Libraries whose declarations would be identical share one
declaration. Blink's and Zap's declarations are in their definition files
(4.4).

## 4. The columns

**4.1** surge is driven through `createCodec<T>()`, fbs through its
`createBinarySerializer<T>()`, and serio through its default-exported
`createSerializer<T>()`.

**4.2** Blink is driven through the `Write` and `Read` its compiler generates
for each exported struct, from `tests/src/bench/definitions/catalog.blink`.

**4.3** Zap has no callable encoder. Its encode fires one event, then calls
`SendEvents`, which hands the queued bytes to the mocked remote the shim
provides ([test-harness.md](test-harness.md) 4.6). Its bytes are the length
of that buffer less the one event-id byte, and the decoder `opt tooling`
generates decodes that buffer. `opt manual_event_loop` is what exposes
`SendEvents`. The remote exists only under Lune, so Zap is a size column
only: `SIZE_ONLY` in `tests/src/bench/adapter.ts` keeps the speed suite off
it.

**4.4** Each of the Blink and Zap definitions, `catalog.blink` and
`catalog.zap`, declares the rows its compiler can express, and the two sets
differ. A row that a definition does not declare has no cell in that column
(3.4). A definition gives each number the width the row's TypeScript
declaration gives it, and leaves each length prefix at its compiler's default.
The compiled modules under `tests/src/bench/blink/` and `tests/src/bench/zap/`
are checked in and regenerated by `mise run bench:definitions`.

**4.5** The baseline column is hand-written Luau in
`tests/src/bench/baseline/codecs.luau`, over three rows: the small flat
struct, the deeply nested object and the `CFrame` array. It must write
surge's bytes exactly, so that its timing measures code rather than format.

**4.6** Every column but serio's runs its codec in modules that carry
`--!native` and `--!optimize 2`: surge's fixtures and the runtime modules its
generated code calls, the baseline's `codecs.luau`, the fbs modules that
build its serialize and deserialize functions, as fbs ships them, and Blink's
generated modules, as its compiler emits them. serio's modules carry neither.

**4.7** A timed call also runs harness code in
`tests/src/bench/speed.spec.ts`, `adapter.ts` and `adapters/`, which carry
`--!optimize 2` and not `--!native`. This is the same for every column.

**4.8** An adapter uses what a library returns the way that library's own
documentation shows, and does no other work in a timed call. surge's adapter
keeps what `serialize` returns as the payload, and passes it to `deserialize`
unchanged. fbs's keeps the table `serialize`
returns and passes its `buffer` and `blobs` to `deserialize`. serio's keeps the `SerializedData`
`serialize` returns and passes it to `deserialize`. Blink's and the
baseline's keep the buffer their write function returns.

## 5. The size tier

**5.1** `mise run bench:size` runs under Lune through
`tests/scripts/lune-size-runner.luau` and the same shim the round-trip suite
uses ([test-harness.md](test-harness.md)).

**5.2** For each cell it records the bytes the adapter reports (Zap's as 4.3
states), the number of values passed outside the buffer, and the largest
difference between any component of the value and its round trip.

**5.3** It writes `docs/benchmarks/size.md`, which records no date, machine
or commit, so that the file changes only when an encoding does.

## 6. The speed tier

**6.1** `mise run bench:speed` builds the tests place and runs the speed
suite, `tests/src/bench/speed.spec.ts`, twice back to back, each run in its
own Roblox Studio process, through `run-in-roblox` and the injected script
`tests/scripts/run-in-roblox-benchmarks.luau`. It never runs under Lune.

**6.2** Each library of a row is first warmed up with 0.1 s of calls. Each
cell then gets nine trials, taken with the row's libraries in turn, one trial
each.

**6.3** A trial is at least 0.2 s of measured calls, timed in chunks of 250
calls, and ends at the first chunk boundary past 0.2 s. Its result is calls
over measured time. Every encode call encodes the row's one sample value,
every decode call decodes the one buffer encoded from it before timing began,
and each call's result is discarded.

**6.4** The suite yields between two chunks once 0.25 s of measured work has
passed since it last yielded, and never inside a timed chunk. It yields three
idle frames between one row and the next.

**6.5** The suite runs the encode and decode halves as one fact, and
`runBenchmarks` returns only after runit's verdict, because `run-in-roblox`
ends the run when the injected script returns.

## 7. Sentinel lines

**7.1** The speed suite prints one `BENCH_ENV: method=…` line describing its
method as its module loads, and one `BENCH_ROW:` line per row, library and
half, carrying every trial's rate.

**7.2** `runBenchmarks` prints one `BENCH_RESULT:` line with runit's verdict:
`PASSED`, `FAILED`, or `ERROR (<reason>)` when the report cannot be parsed,
no test ran, or the runner throws.

**7.3** `runBenchmarks` prints one `BENCH_ENV: engine=…` line, with the
engine version, before the suite runs.

## 8. The speed results files

**8.1** `tests/scripts/record-speed-benchmarks.mjs` wraps `run-in-roblox`,
forwards every line, and writes `docs/benchmarks/speed.md` and
`docs/benchmarks/speed-trials.tsv` only if every run printed
`BENCH_RESULT: PASSED` and returned every row in both halves. An interrupted
invocation leaves both files as they were.

**8.2** Both files record the date, the machine, the engine version the
process reports, and the commit or version of everything measured. A
repository with uncommitted changes or untracked files is marked as having
uncommitted changes.

**8.3** `speed-trials.tsv` holds every trial of every run.

**8.4** A cell in `speed.md` is the median of its trials pooled across both
runs. Its `±` is `(high - low) / median`, where `low` and `high` are the
trials at zero-based positions `floor(n / 4)` and `floor(3n / 4)` of the `n`
pooled trials sorted in ascending order. A cell's drift is the difference
between its two runs' medians over its pooled median. The file states the
largest drift of any cell, and the ninth decile of all cells' drifts.

**8.5** A cell whose `±` or drift exceeds 10% is marked `†`. A ratio against
surge is marked `†` when either of its two cells is.

**8.6** `mise run bench:speed:render` rewrites `speed.md` from
`speed-trials.tsv` without a run.

**8.7** The summary gives, per library other than surge and per half, the
geometric mean of that library's throughput over surge's, across the rows
where both have a cell and neither cell is marked. It states how many of the
rows both have that mean covers.

## 9. Scoped runs

**9.1** `mise run bench:size:only` and `mise run bench:speed:only` take
patterns and run only the rows they select. A pattern selects a row when,
with case and every character that is not a letter or digit removed from
both, the pattern is contained in the row's name. Both tiers select through
`tests/src/bench/selection.ts`.

**9.2** A scoped run prints its tables and writes no results file. A scoped
speed run is one run, not two.

**9.3** A `:only` task given no pattern, or a pattern that selects no row,
stops without measuring.

## 10. Rebuilding before a run

**10.1** Both tiers run `tests:install` and `tests:compile` before measuring,
for the reasons in section 6 of [test-harness.md](test-harness.md).
